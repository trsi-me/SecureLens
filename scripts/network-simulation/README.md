# محاكاة الشبكة (GNS3 / EVE-NG)

GNS3 و EVE-NG أدوات محاكاة شبكات مستقلة تعمل خارج كود المشروع (تُشغَّل على جهاز أو خادم منفصل
وتستورد أجهزة افتراضية Router/Switch/Firewall)، لذلك لا يمكن "تضمينها" داخل تطبيق Flask نفسه.
هذا الملف يوضح كيف يوضع خادم SecureLens داخل تصميم شبكة مُحاكاة عند استخدام أي من الأداتين
لأغراض تدريبية أو اختبارية قبل النشر الفعلي.

## التصميم المقترح للمحاكاة

```
Internet (Cloud icon)
      │
   [Firewall]
      │
   [Router]
      │
  ┌───┴────┐
  │ VLAN10 │  شبكة DMZ (تحتوي خادم SecureLens + خادم OpenVPN)
  └───┬────┘
      │
  ┌───┴────┐
  │ VLAN20 │  شبكة إدارية داخلية (وصول المسؤولين عبر VPN فقط)
  └────────┘
```

## خطوات الإعداد داخل GNS3 أو EVE-NG

1. أضف جهاز Firewall افتراضي (pfSense مثلاً) بين الإنترنت وباقي الشبكة.
2. أضف Router/Switch لفصل شبكة DMZ عن الشبكة الإدارية بواسطة VLANs.
3. أضف جهاز Linux (Ubuntu Cloud Image أو ما شابه) داخل VLAN الخاصة بـ DMZ، وثبّت عليه
   SecureLens باستخدام `scripts/setup_linux.sh`.
4. اربط قواعد الجدار الناري بحيث لا يُسمح بالوصول لمنفذ الإدارة (SSH) إلا عبر واجهة OpenVPN
   (راجع `security-tools/openvpn/server.conf.sample`).
5. صدّر التصميم كملف `.gns3project` أو `.unl` (بحسب الأداة) واحفظه مع توثيق المشروع.

> ملاحظة: هذا توثيق لتصميم الشبكة المحيطة بالتطبيق، أما SecureLens نفسه فهو تطبيق ويب يعمل
> بشكل مستقل داخل أي عقدة Linux/Windows بالشبكة المحاكاة.
